# Flutter Build Troubleshooting — Handoff State

**Purpose:** transient notes so a fresh Claude Code session can resume the `flutter run` troubleshooting for `tbt_app` (Flutter workspace of the TBT monorepo). Delete this file once the build works reliably.

## What we're trying to do

Get `flutter run` to build and launch `tbt_app` on the user's Vivo V2319 phone (arm64, USB-connected, USB debugging on). Backend + web workspaces are unrelated.

## Fixes already applied

1. **`android/app/build.gradle.kts`** — `compileSdk = 36` (hardcoded, up from `flutter.compileSdkVersion`) because `flutter_webrtc` requires it. `com.google.gms.google-services` plugin added by flutterfire configure.

2. **`android/gradle.properties`** — currently at ultra-conservative settings to avoid Windows commit-limit exhaustion (`errno 1455 / DartWorker: 22`):
   - `-Xmx2G -XX:MaxMetaspaceSize=512m` for Gradle
   - `kotlin.daemon.jvmargs=-Xmx1500m` (Kotlin daemon forks its own JVM)
   - `org.gradle.workers.max=1`, `parallel=false`
   - `kotlin.incremental=false` — works around `RelocatableFileToPathConverter` IllegalArgumentException because pub cache is on `C:\` and project is on `F:\` (different drive letters crash `File.relativeTo()`)

3. **Firebase configured** — `flutterfire configure` was run, `lib/firebase_options.dart` now has real values (was placeholders → previous crash cause), `android/app/google-services.json` present.

4. **Windows pagefile bumped** — registry `HKLM\SYSTEM\CurrentControlSet\Control\Session Manager\Memory Management\PagingFiles = C:\pagefile.sys 16384 32768`, `AutomaticManagedPagefile = false`. **Requires reboot** to take effect.

## Current step (where the user is now)

**Just applied the pagefile registry change and is about to reboot.** After reboot they need to:

1. **Verify pagefile actually took effect:**
   ```powershell
   Get-CimInstance Win32_PageFileSetting | Select Name, InitialSize, MaximumSize
   ```
   Should show `C:\pagefile.sys 16384 32768`.

2. **Retry `flutter run` from `F:\admin\tbt_app`** with phone connected.
   - Suggest: `flutter run --dart-define=API_BASE_URL=<real backend URL>` — default is `http://localhost:8000` which is unreachable from phone AND cleartext HTTP (Android 9+ blocks by default). Prod URL should match `NEXT_PUBLIC_API_URL` from web workspace.

3. **If build succeeds:** relax `gradle.properties` back to `-Xmx4G` / `workers.max=2` for speed. The tight limits are only needed while pagefile was small.

4. **If build still crashes with DartWorker: 22:** something else is committing memory. Check emulator (should be killed), zombie java processes, browser tabs. Kill them.

5. **If build succeeds but app crashes on phone:** get the runtime crash log with `flutter run` output OR `adb logcat -s AndroidRuntime:E flutter:V DEBUG:E "*:F"`. Suspects: cleartext HTTP to backend URL, missing runtime permission on Android 13+, plugin native lib missing for arm64.

## Key context that isn't obvious from the code

- The Flutter app talks to the **same Fastify backend** as `tbt-user-web`, using **JWT cookies**, not Clerk. See root `CLAUDE.md` for backend module layout.
- `main.dart` synchronously waits on 3 site-config API calls before `runApp()` — network failure there = silent hang on splash (handlers catch errors so no crash, just no data).
- `_TbtAppState.build()` eagerly fires socket connection + FCM handlers + workshop/course/batch event handlers on first render. Any of these throwing = splash then close pattern.
